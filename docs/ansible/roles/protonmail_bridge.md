# protonmail_bridge

Installs the Proton Mail Bridge in headless mode so that local applications can
send and read mail through IMAP and SMTP on the loopback interface. The role
prepares everything around the Bridge: a dedicated system user, a GPG key and a
`pass` store for the credentials the Bridge keeps, a systemd unit and a helper
for the one-time interactive login.

## Requirements

- A Debian-family `amd64` target (Proton only publishes an amd64 package; the
  role asserts it).
- A paid Proton account with Bridge access.
- Outbound HTTPS access to `proton.me`.
- Someone able to log in once on the host: the Bridge cannot authenticate
  unattended, so the role stops short of starting it (see below).

## Usage

```yaml
- hosts: mail
  become: true
  roles:
    - role: goabonga.website.protonmail_bridge
      vars:
        protonmail_bridge_version: "3.14.0"
        protonmail_bridge_log_level: warn
```

Run it alone with `--tags protonmail_bridge`.

### One-time login

After the first run, log in as the service user:

```bash
sudo -u protonmail /var/lib/protonmail-bridge/bridge-setup.sh
```

In the Bridge CLI run `login` (and complete two-factor authentication if it is
enabled), then `info` to read the IMAP/SMTP username and the Bridge password.
That password is generated by the Bridge and is not your Proton password. Store
it in a vault and hand it to the application that reads or sends mail. Then
start the service:

```bash
sudo systemctl start protonmail-bridge
```

Set `protonmail_bridge_service_state: started` once the login is done if you
want later runs to keep the service running. The default, `unmanaged`, only
enables the unit at boot and never starts or stops it.

To log in again after a token expiry, stop the service, run the helper, then
start the service.

## What it does

1. Validates the target (Debian family, amd64 package).
2. Installs the dependencies (`pass`, `gnupg2`, a secret service, D-Bus) and
   makes sure D-Bus is running.
3. Installs the Bridge package. The installed version is read with
   `dpkg-query`; the `.deb` is only downloaded when it is older than
   `protonmail_bridge_version`.
4. Creates the service group and user, enables systemd lingering so that
   `/run/user/<uid>` exists, and creates the runtime, configuration, cache,
   GnuPG and password-store directories (mode `0700`).
5. Generates a GPG key without passphrase and initialises `pass` with it, unless
   `protonmail_bridge_manage_gpg` is false. Both steps are skipped when they are
   already done.
6. Renders the systemd unit, the login helper and, according to
   `protonmail_bridge_service_state`, manages the service.
7. Prints the login procedure unless `protonmail_bridge_show_instructions` is
   false.

The runtime directory is derived from the real UID of the service user, not
hard-coded, and can be overridden with `protonmail_bridge_runtime_dir`.

## Connection details

The IMAP and SMTP endpoints belong to the Bridge itself (it listens on
`127.0.0.1:1143` and `127.0.0.1:1025` by default). The `imap_*` and `smtp_*`
variables of this role do not reconfigure the Bridge: they only fill the login
helper and the final message. If you change the ports from the Bridge CLI, set
the same values here to keep the messages accurate.

## Variables

### Role control

| Variable | Type | Default | Description |
| --- | --- | --- | --- |
| `protonmail_bridge_enabled` | bool | `true` | Master toggle. When false the role does nothing. |
| `protonmail_bridge_apt_update_cache` | bool | `true` | Refresh the apt cache before installing packages. |
| `protonmail_bridge_apt_cache_valid_time` | int | `3600` | Seconds the apt cache is considered fresh. |

| --- | --- | --- | --- |

| `protonmail_bridge_version` | str | `"3.14.0"` | Bridge release to install (see https://proton.me/mail/bridge). |

| `protonmail_bridge_deb_checksum` | str | `""` | Optional checksum of the .deb in the `algorithm:value` form accepted by get_url. |

| --- | --- | --- | --- |
| `protonmail_bridge_user` | str | `"protonmail"` | System user running the Bridge. |
| `protonmail_bridge_group` | str | `"protonmail"` | Primary group of the service user. |

| `protonmail_bridge_gpg_key_length` | int | `4096` | GPG key length in bits. |

## Handlers

| Topic | Effect |
| --- | --- |
| `protonmail_bridge \| reload systemd` | Runs `systemctl daemon-reload`. |
| `protonmail_bridge \| restart` | Restarts the unit (only when `protonmail_bridge_service_state` is `started`). |

## Security notes

- The GPG key has no passphrase because the service restarts unattended. Anyone
  who can read `protonmail_bridge_home` can read the stored Bridge credentials;
  the directories are `0700` and owned by the service user.
- The unit limits memory and CPU (`protonmail_bridge_memory_max`,
  `protonmail_bridge_cpu_quota`); set them to an empty string to lift a limit.

## Verification status

The role is checked with `ansible-playbook --syntax-check`, the argument
specification is validated against the defaults and the systemd unit and helper
script are rendered locally. It has not been run against a live host: the
package installation, the GPG and pass initialisation, lingering and the
service start are untested, and the login flow needs a real Proton account.
