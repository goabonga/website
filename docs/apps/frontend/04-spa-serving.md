# SPA serving

This feature makes the server deliver the website. Every path that no other
route handles returns the Jinja2 template generated by the
[web client](03-web-client.md), filled with the runtime configuration, and the
client build is served under `/static`. One build can therefore be deployed to
any environment: only the environment variables change.

## Routes

| Method | Path | Description |
|--------|------|-------------|
| GET | `/static/*` | Files of the Vite build (`assets/index.js`, `assets/index.css`). Mounted only when the build directory exists. |
| GET | `/{path}` | Catch-all: renders `templates/index.html` with status `200` and an HTML content type. |

The catch-all is registered last in `create_app`, so `/health` and the
documentation routes (when `DOCS_ENABLED=true`) are never shadowed. When the
documentation is disabled, `/docs`, `/redoc` and `/openapi.json` are no longer
registered and fall through to the catch-all, which returns the application
page. Unknown files under `/static` answer `404` when the build directory is
mounted, and the page otherwise.

## Template context

`frontend.main.template_context(settings)` builds the values passed to the
template. Jinja2 autoescaping is active, so values are HTML-escaped in the
page; the values of the `window.APP_CONFIG` script go through the `tojson`
filter instead, so that the web client reads them unchanged.

| Template variable | Setting |
|-------------------|---------|
| `app_name` | `APP_NAME` |
| `auth_url`, `api_url`, `analytics_url` | `AUTH_URL`, `API_URL`, `ANALYTICS_URL` |
| `client_id` | `OAUTH2_CLIENT_ID` |
| `welcome_name`, `welcome_words` | `WELCOME_NAME`, `WELCOME_WORDS` |
| `legal_*` | `LEGAL_*` |
| `social_*` | `SOCIAL_*` |

The Phone and website lines of the hosting provider are only rendered when
`LEGAL_HOST_PHONE` and `LEGAL_HOST_WEBSITE` are set.

## Settings

| Variable | Default | Description |
|----------|---------|-------------|
| `STATIC_DIR` | empty | Directory mounted on `/static`; empty means `apps/frontend/web/dist` (relative to the source tree) |
| `AUTH_URL` | empty | Base URL of the OAuth2 / OIDC server, used by the client |
| `API_URL` | empty | Base URL of the API, used by the client |
| `ANALYTICS_URL` | empty | Base URL of the analytics service, used by the client |
| `OAUTH2_CLIENT_ID` | empty | Public PKCE client id of the client (not a secret) |
| `LEGAL_COMPANY_NAME` | `GOABONGA` | Legal notice: company |
| `LEGAL_ADDRESS`, `LEGAL_CITY`, `LEGAL_COUNTRY` | empty | Legal notice: postal address |
| `LEGAL_DIRECTOR_NAME` | empty | Legal notice: publication director |
| `LEGAL_HOST_NAME`, `LEGAL_HOST_ADDRESS`, `LEGAL_HOST_CITY`, `LEGAL_HOST_COUNTRY`, `LEGAL_HOST_PHONE`, `LEGAL_HOST_WEBSITE` | empty | Legal notice: hosting provider |
| `WELCOME_NAME` | `Chris` | Name in the welcome message |
| `WELCOME_WORDS` | `super,cool,awesome,great` | Comma-separated words animated in the welcome message |
| `SOCIAL_LINKEDIN`, `SOCIAL_GITHUB`, `SOCIAL_HUGGINGFACE` | empty | Profile links |

Nothing here is a secret. The application depends on `jinja2` for rendering.

## Running with the client build

```bash
npm --prefix apps/frontend/web ci
npm --prefix apps/frontend/web run build
cd apps/frontend && uv run --package frontend uvicorn frontend.main:app --port 8000
```

Without the build the page is served but its scripts and styles return the
page itself instead of the assets.

## Tests

pytest (`tests/test_spa.py`, plus the defaults of the new settings): page on
any path, injection of every setting, welcome words, HTML escaping, values of
the JavaScript configuration written as JSON (quotes, `&` and a closing script
tag cannot alter the script), optional phone line, a check that the context provides exactly the variables used by
the template, static files served or skipped, the catch-all not shadowing
`/health` and the documentation switch.

behave (`features/spa_serving.feature`, steps in
`features/steps/spa_serving_steps.py`):

- Every unknown path serves the application page
- Runtime settings are injected in the page
- Welcome words come from the settings
- Settings values are escaped in the page
- Client build files are served under /static
- Missing static files are reported as not found
- Without a client build the page is still served
- The health check is not shadowed by the application page

The scenarios use a temporary directory as the client build.

browser (`features/browser/spa_serving.feature`, tag `@browser`, see [Browser
testing](../../testing/index.md); steps in `features/steps/browser_common_steps.py`
and `features/steps/browser_spa_serving_steps.py`): the scenarios build the web
client from its sources (`npm ci` and `npm run build` in a temporary copy of
`web/`, once per run) and serve the application on a real socket with the
settings of the scenario, then open it in Chromium with the console watched:

- The application page boots the web client
- The runtime settings reach the web client
- Settings with special characters reach the web client unchanged
- The static files of the build are served with the page
- Every path is served by the catch-all (`/`, `/pricing`, a deep route,
  `/login`)
- The web client handles its own callback route
- Missing static files are reported as not found
- The health check is not shadowed by the application page
- The menu lists the profile links of the settings
- The legal notice shows the publisher and the host of the settings
- Without a client build the page opens but the web client cannot start (the
  script request returns the page, which the browser refuses as a module)

They are skipped, with the reason, when `node` or the npm registry is not
available. The request for the Google font is answered with an empty style
sheet and any other third-party request fails the scenario.
