# Commit messages

The signed merge replays every commit of a pull request through
`scripts/sign_commit.py`, which refuses a subject that is not a Conventional
Commit, is longer than 72 characters or ends with a period. By then the pull
request is labelled and queued. `scripts/check_commit_subject.py` applies the
same rule first, and adds the rules of `CLAUDE.md` that the merge cannot
enforce.

## Rules

A message is refused when:

- the subject is not `<type>(<scope>): <summary>`, is longer than 72
  characters, ends with a period, or its summary does not start with a
  lowercase letter;
- the type is not one of `feat`, `fix`, `refactor`, `test`, `docs`, `chore`,
  `style`, `perf`, `build`, `ci` and `revert`;
- a scope is given and is not one of the "Commit scopes" of `CLAUDE.md`: an
  application, `ansible`, `workspace`, `multicz` or `site`. The scope is
  optional;
- a line is a `Co-Authored-By` trailer or starts with `Generated with` or
  `Generated by`;
- the message contains an emoji;
- the subject has the `!` marker and the message has no `BREAKING CHANGE:`
  footer.

Every reason is reported, with the abbreviated hash in CI. The scope list is a
constant of the script; a test keeps it equal to `CLAUDE.md` and checks that
every directory of `apps/` is in it, so a new application cannot be added
without the list following.

## Where it runs

- **Locally**, as the `commit-subject` `commit-msg` hook of `pre-commit`
  (`uv run pre-commit install -t pre-commit -t commit-msg`). The hook lets
  autosquash commits (`fixup!`, `squash!`, `amend!`) through: they are meant
  to be squashed away before the pull request.
- **In `ci`**, as the `commit-messages` job, on the commits of a pull request
  (`python3 scripts/check_commit_subject.py --range BASE..HEAD`). Here a
  `fixup!` commit is refused, since the signed merge would refuse it too.
  Merge commits are skipped, and so are the `deploy/` branches, whose only
  commit is the `chore(release)` bump written by `multicz`.

The check is stricter than the signed merge on purpose: the merge accepts any
scope, and also the `deprecate` and `remove` types configured in
`multicz.toml`, which are not in the list of types of this repository.

Run it by hand on a range, for example the commits of your branch:

```sh
python3 scripts/check_commit_subject.py --range origin/main..HEAD
```
